# LuminPro — 日用屏幕亮度强化

**中文简体** 丨 [English](https://github.com/YuleBest/LuminPro/blob/main/README_en.md)

让你的 Android 设备随时可以突破前台亮度上限，将屏幕提升至硬件峰值  
_基于 KernelSU WebUI + Rust 事件驱动架构_

</div>

## 模块介绍

无论当前屏幕亮度如何，只要触发亮度超过设定阈值，LuminPro 便会自动且平滑地将屏幕提升至硬件支持的峰值亮度，确保你在强光户外也能获得清晰的显示效果。模块采用 Rust 编写的 `lumipro` 二进制程序进行底层文件事件监听，零轮询、零空转，配合 KernelSU WebUI 提供完整的可视化配置与状态监控。

> [!TIP]
> 如果你是开发者，请参阅 [开发文档 (DEVELOPMENT.md)](./DEVELOPMENT.md) 了解构建与调试流程。

## V2.3+ 核心特性

- **零耗电底层监听 (lumipro)**  
  彻底告别死循环与轮询。使用 Rust 编写的 `lumipro` 二进制程序替代 `inotifyd`，内置防抖动与调试模式，仅在亮度节点文件发生变更的瞬间响应，守护进程 (`daemon.sh`) 负责持续监视 lumipro 进程稳定性，并具备**失效自动修复（Stale Lock 回收）**机制。

- **兼容模式 (轮询驱动)**  
  针对部分无法触发 inotify 事件的特殊机型，新增兼容模式。开启后模块切换为 2 秒一次的低频轮询，确保在任何环境下都能正常工作。

- **KernelSU WebUI 可视化配置**  
  在管理器的模块设置页面中，通过暗色面板实时调整所有参数，保存后**立即生效**，无需重启：
  - `前台最大亮度` — 触发提升的亮度阈值
  - `峰值最大亮度` — 提升后的目标硬件亮度
  - `调整步数` — 平滑过渡的步进数（默认 50 步）
  - `休眠时段` — 指定不触发提升的时间范围（如 `2200-0700`）
  - `日志等级` — 控制日志输出量（关闭 / 仅错误 / 警告+ / 全部）
  - `亮度/最大亮度节点路径` — 支持自定义设备 sysfs 路径
  - `inotify 监测事件` — 自定义 lumipro 触发事件类型

- **平滑亮度过渡**  
  毫秒级 50 步步进算法，避免亮度瞬间跃升带来的视觉不适。步数可在 WebUI 中自由调整。

- **智能跳过机制**  
  以下情况模块将自动跳过本次提升，避免干扰正常使用：
  - 系统自动亮度已启用
  - 当前正在播放 HDR 内容（可配置，采用双阈值状态机避免忽明忽暗）
  - 当前前台应用在黑名单中
  - 处于配置的休眠时段内

- **HDR 智能状态机**  
  播放 HDR 内容时，模块采用**双阈值滞后 + 冷却期**的状态机机制：
  - 进入 HDR：`hdrSdrRatio` 超过进入阈值（默认 1.10）时确认 HDR 状态
  - 退出 HDR：`hdrSdrRatio` 低于退出阈值（默认 1.03）时才退出，中间区域保持当前状态
  - 冷却期：进入 HDR 后持续 N 秒（默认 8 秒）内不再重复检测，避免比率波动导致振荡
  - 进入 HDR 时自动平滑恢复亮度到阈值以下，避免峰值亮度干扰 HDR 显示效果
  - 彻底解决 HDR 场景下亮度忽明忽暗的问题

- **应用黑名单**  
  在 WebUI 的「应用」页面中管理黑名单，支持按包名搜索、Activity 精准匹配（可通过内置扫描工具自动获取前台 Activity 名）。黑名单内的应用处于前台时，模块不执行亮度提升。

- **一键峰值触发 (boost.sh)**  
  通过管理器的「操作」按钮或 `action.sh` 快捷开关，可即时将亮度拉至峰值；再次触发则恢复原始亮度。

- **实时状态监控与日志**  
  WebUI 状态页实时显示当前亮度值、lumipro 运行 PID 及服务状态。日志页支持按 `INFO` / `WARN` / `ERROR` 等级过滤，并可一键复制或导出到 `/sdcard`。

## 配置项说明

| 配置项              | 说明                            | 默认值            |
| ------------------- | ------------------------------- | ----------------- |
| `ui_max_bri`        | 前台触发阈值（UI 亮度值）       | `0`（需手动校准） |
| `max_bri`           | 峰值目标亮度                    | `0`（需手动校准） |
| `compatibility_mode`| 兼容模式（轮询驱动）            | `0`（禁用）       |
| `steps_num`         | 亮度过渡步数                    | `50`              |
| `sleep_time`        | 休眠时段，格式 `HHMM-HHMM`      | 空（禁用）        |
| `auto_bri_sleep`    | 自动亮度开启时跳过              | `1`（启用）       |
| `display_hdr_sleep` | HDR 内容时跳过                  | `0`（禁用）       |
| `hdr_enter_threshold` | HDR 进入阈值（hdrSdrRatio 大于此值确认 HDR） | `1.10` |
| `hdr_exit_threshold`  | HDR 退出阈值（hdrSdrRatio 小于此值退出 HDR） | `1.03` |
| `hdr_cooldown`      | HDR 状态冷却期（秒），期间保持跳过 | `8`           |
| `log_level`         | 日志等级（off/error/warn/info） | `info`            |
| `log_max_size`      | 日志文件大小上限（KB）          | `512`             |
| `now_bri_file`      | 当前亮度节点路径                | 标准 panel0 路径  |
| `max_bri_file`      | 最大亮度节点路径                | 标准 panel0 路径  |
| `blacklist_apps`    | 黑名单包名/Activity 列表        | `[]`              |
| `inotify_events`    | lumipro 监测事件                | `c`               |

## 安装方法

1. 在支持 KernelSU WebUI 的管理器中刷入模块 ZIP。
2. 在音量键安装向导中完成亮度校准（若已有旧版配置，按音量上键直接继承跳过）。
3. 重启设备生效。
4. 在管理器模块设置页调整各项参数，点击保存立即生效。

## 注意事项

> ⚠️ **OLED 烧屏与发热警告**  
> 长期维持峰值亮度会显著加剧 OLED 屏幕老化与烧屏风险，并大幅增加设备发热与耗电。请根据使用场景合理配置，切勿超出设备硬件安全范围。

- 确保填写的亮度数值在设备硬件支持的安全范围内。
- HDR 跳过功能默认关闭，需在 WebUI 中手动开启 `display_hdr_sleep`。
- 若 HDR 场景仍有轻微波动，可适当调大 `hdr_enter_threshold`（如 1.15）或延长 `hdr_cooldown`（如 12）。
- 遇到问题时，请通过 WebUI 日志页导出运行日志后反馈至社区。
